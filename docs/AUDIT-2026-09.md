# WhatStack engine and runtime audit (September 2026, v1.7.2)

**Scope:** the detection algorithm (`shared/detect.js`, `shared/signatures.js`, matcher and classifier), the MV3 runtime (service worker, orchestrator, content script, popup), exports and the report link, the tests and tooling.

**Method:**
- A full code read.
- Reproductions: the real `detect()` and the real MAIN-world probe (run in `node:vm`), fed crafted inputs.
- A live benchmark: the unpacked extension loaded into Chromium on **48 real sites**, reading the light badge, then the deep popup result and its evidence.

Every **Confirmed** finding below was reproduced. The rest come from the code read and are marked **(code)**.

---

## 1. Summary

The architecture is sound. There is a pure engine, and evidence comes only from asset URLs, runtime globals and probed DOM flags, never page prose. The popup renders safely (`textContent` everywhere). The report link keeps the "Local only" promise. Real deep scans are fast: **median 46 ms, max 208 ms**.

The main weaknesses are **trust in page-controlled values** and **pattern breadth**. The same few flaws produce most of the bad results:

| Area | Result on 48 real sites |
|---|---|
| Badge ≠ popup count | **27 / 48 (56%)**: the badge comes from a pass that can't see JS runtime state |
| Tailwind reported MEDIUM from class names alone | **17 / 48**, including **getbootstrap.com** (a Bootstrap site) |
| Wrong framework version shown | linear.app "Next.js **v1.0.0-beta.9**", angular.dev "v22.2.0**+sha**" |
| Plainly wrong hit | clerk.com **Bootstrap HIGH**, from Clerk's own `…/bootstrap.js` loader |
| Nothing detected | youtube.com (Polymer), amazon.in, zomato.com, plus astro.build detected only as Tailwind |

In the crafted reproductions (§3), a single `<a id="next">` on any page yields **Next.js HIGH + React HIGH**. A blog post about micro-frontends inside a JSON data island yields **four HIGH microfrontend hits**. One throwing getter on the page **erases every runtime detection** for that scan.

## 3. Confirmed detection bugs

Reproduced with the real engine. The repro script is in §9.

### C1 — `window.next` is trusted as proof of Next.js and its version (Critical)
- **Where:**
  - the probe `const next = tryGet('next')` (detect.js ~L258)
  - the signature `{type:'global', pattern:'next', weight:2, runtime:true}` (signatures.js ~L45)
  - `take('nextjs', g.next.version)` (extractVersions ~L608)
  - `n.confidence = 'high'` (resolveStack ~L900)
- **Repro:**
  - `globals:{next:{version:'1.0.0-beta.9'}}` gives `nextjs:high@1.0.0-beta.9 react:high`
  - `globals:{next:<element>}` gives `nextjs:high react:high`
- **Why:** HTML elements with an `id` or `name` become window properties (DOM clobbering), so any "Next" button with `id="next"` counts. Linear really does ship `window.next = {version:'1.0.0-beta.9', appDir, router}`, which looks like a Next-compatible runtime. That number is not a Next.js version.
- **Fix:**
  - Accept `window.next` only when it is a plain object (not a `Node`), `version` is a string, and the major version is ≥ 9.
  - Treat it as a version source only, never as proof.
  - Stop forcing Next.js to `high` without strong evidence.
  - If the version fails validation, show it with no version rather than a wrong one.

### C2 — A single throwing getter wipes the whole deep probe (Critical)
- **Where:** property reads outside `tryGet`: `jq.fn.jquery`, `hook.renderers`, `React.version`, `Vue.*`, `System.*`, `Sentry.*`, `NREUM.info…`, `firebase.apps` (detect.js L92–330).
- **Repro:** `Vue = new Proxy({}, {get(){throw}})` next to a real `__NEXT_DATA__` → the probe throws → `probeMainWorld` returns `{}` → **all runtime evidence is lost**. The same happens for a jQuery `fn` getter that throws.
- **Fix:**
  - Wrap each detector block in its own try.
  - Add a `safe(obj, key)` helper, cap page strings at 64 chars, and never `String()` page objects (that runs page `toString`).

### C3 — DOM clobbering spoofs "truthy-only" globals (High)
- **Where:**
  - `ng`, `bootstrap`, `axios`, `gtag`, `mixpanel`, `__PINIA__`, `__MOBX__`, `__APOLLO_CLIENT__`
  - `Clerk`, `auth0`, `LogRocket`, `DD_RUM`, `LDClient`, `__FEDERATION__`
  - the TanStack and Remix loops (detect.js ~L282, L440–481)
- **Repro:** `<div id="bootstrap">`, `<div id="axios">`, `<div id="ng">` give **Bootstrap HIGH, Axios HIGH, Angular MEDIUM (primary)**.
- **Fix:**
  - An `isRealObject(v)` guard (reject `Node`, `HTMLCollection`, `WindowProxy`).
  - A per-library shape check (`typeof axios.get==='function'`, `typeof gtag==='function'`, `typeof mixpanel.track==='function'`, `bootstrap.Modal`, …).

### C4 — Asset patterns match any URL fragment, including images and API queries (High)
- **Where:** `isAssetLike` accepts any `https://` URL, and the pool includes **every** performance resource entry. Unanchored patterns:
  - `logrocket`, `zendesk`, `razorpay`, `launchdarkly`, `qiankun`
  - `turbopack`, `styled-components`, `@mui/|material-ui`, `parcel(Require|.js)`
  - `bootstrap(.bundle)?(.min)?.js`, `hotjar.com`, `mixpanel.com`
- **Repro:** `/img/logrocket-vs-zendesk.png` + `/api/search?q=qiankun` → **LogRocket HIGH, Zendesk HIGH, qiankun HIGH, Microfrontend HIGH**.
- **Live:** clerk.com → **Bootstrap HIGH** from `cdn.protect.clerk.com/…/bootstrap.js` (a loader file name, not the CSS framework).
- **Fix:**
  - Match against the parsed `URL` (host + pathname, never the query).
  - Anchor to package boundaries (`/(?:^|\/)(?:npm\/)?bootstrap@|\/bootstrap(?:\.bundle)?(?:\.min)?\.js$/` **plus** a CDN or version check).
  - Keep only `initiatorType` script, link or css from the performance entries.

### C5 — Inline regexes read JSON data islands and prose (High)
- **Where:** `inlineSamples` includes `application/json`, `ld+json`, `__NEXT_DATA__` and Nuxt payloads. The patterns include `/module federation/i`, `/single-spa/i`, `/qiankun/i`, `createServerFn|StartClient`, `react-router-dom` and `\b__NEXT_DATA__\b`.
- **Repro:** a Next blog post titled *"Migrating to single-spa and module federation with qiankun"* → **Module Federation, single-spa, qiankun, Microfrontend: all HIGH**. This breaks the product's own rule, "never page copy".
- **Fix:**
  - Sample only executable scripts (no `type`, `text/javascript` or `module`).
  - Require code-shaped patterns (`window.__POWERED_BY_QIANKUN__`, `singleSpa.registerApplication(`), never English words.

### C6 — Tailwind is counted twice and triggered by Bootstrap class names (High)
- **Where:** `detect()` ~L1250 adds `utility class density` whenever no snippet contains `"utility"`. The existing flag is `tailwind-utilities` ("utilit**ies**"), so both are added: total = 2, which scores **medium**. `utilRe` (content-script ~L92) matches `flex`, `text-center`, `rounded`, `shadow`, which Bootstrap also uses.
- **Live:** **getbootstrap.com → Tailwind CSS MEDIUM**. It counts in the badge on **17/48** sites. The existing test is conditional and asserts nothing (`if (tw && tw.confidence==='low')`).
- **Fix:**
  - Remove the synthetic push.
  - Detect Tailwind from Tailwind-only syntax: variant prefixes (`md:`, `hover:`), arbitrary values (`w-[42px]`), slash opacity (`bg-black/50`), `space-x-4`, and the `--tw-` custom properties.
  - Class names alone should stay **low**.

### C7 — Version regexes capture the wrong package (Medium)
| Input | Output | Cause |
|---|---|---|
| `@remix-run/react@2.12.0` | **React 2.12.0** | `(?:^|[\/@])react@` matches after the scope |
| `@tanstack/react-router@1.58.0` | **React Router HIGH @1.58.0** (a spurious *hit* too) | unanchored `react-router@` |
| `react-bootstrap@2.10.2` | **Bootstrap 2.10.2** (and Bootstrap HIGH) | `bootstrap[@\/_-]([\d.]+)` |
| `/js/preact-10.19.js` | **React 10.19** | `react[_-]([\d.]+)\.js` |
| inline `{"next":"1700000000.5"}` | **Next.js 1700000000.5** | `"next":"x"` over any JSON |
| `ng-version="22.2.0+sha-14793bf"` | "22.2.0+sha" | `normalizeVersion` truncates the build metadata |

**Fix:**
- Anchor every package regex with a negative scope look-behind (`(?<![\w@-]\/)(?<!@[\w-]+\/)react@`).
- Validate plausible major versions per technology.
- Pick the React version from the `react-dom` renderer rather than the last registered one.
- Keep prerelease and build text intact, or drop it cleanly.

### C8 — Weak "medium" rules (Medium)
- `sc-button` (any `sc-` design-system class) → **styled-components MEDIUM**. Real class hashes look like `sc-[a-zA-Z]{5,}`, or the page has `[data-styled]`.
- `/api/auth/session` → NextAuth medium. Any `…/graphql/…` path → GraphQL medium.

### C9 — Wrong global names produce false negatives (Medium)
| Tech | Engine looks for | What real sites expose (checked live) |
|---|---|---|
| Turbopack | `__turbopack` | `TURBOPACK` (nextjs.org). It is only caught by the inline regex |
| SvelteKit | `__sveltekit` | `__sveltekit_<hash>` (svelte.dev) |
| Svelte 5 version | — | `__svelte.v` is a `Set` holding `'5'` (stackoverflow.com). The version is never read |
| React (no DevTools) | fiber keys on `#root`/`#app`/first 12 body children | `document._reactListening…` (airbnb.com) is never checked |
| Angular emulated styles | `[class*="_ngcontent-"]` | `_ngcontent-*` is an attribute *name*, so this selector never matches (dead) |
| Vue 2 | — | `el.__vue__` is never checked |
| Webpack 4 | — | `webpackJsonp` global is never probed |

### C10 — Coverage gaps seen live (Medium)
There are no signatures for:
- **Astro** (astro.build has `meta generator="Astro v7.3.3"` and `data-astro-*`)
- **Polymer / Lit / web components** (youtube.com has `window.Polymer` and `ytd-*` elements)
- Preact, Qwik, Gatsby, Ember, Alpine.js, htmx
- platforms: WordPress, Shopify, Webflow, Framer
- analytics: PostHog, Plausible, Fathom, Amplitude, Vercel Analytics (clerk.com exposes `__PosthogExtensions__`; remix.run loads Fathom)

### C11 — First-party vs third-party attribution (Low, product)
hotjar.com shows **Parcel HIGH**. The `parcelRequire` global most likely comes from an embedded third-party script, not the site's own build; the Module Federation hit there *is* real (`remoteEntry.js` + `__FEDERATION__`). Evidence from other origins should be labelled as third-party, or counted with less weight, for build tools.

## 4. Runtime (MV3) findings

### R1 — The badge doesn't match the popup on 56% of sites (Critical)
**Cause:** the light pass runs in the content script's isolated world. It shares the DOM but **not the page's JS heap**, and it posts `globals: {}`. So React fibers, `el.__vue_app__`, `window.Stripe`, `__NEXT_DATA__` and `jQuery` can only be seen by the deep probe, which runs **only when the popup opens**. After that, a later light message (the 1.5 s timer, or `popstate`) **puts the badge back to the lower count**.

**Examples (light → deep):**

| Site | Light | Deep |
|---|---|---|
| vuejs.org | *(empty)* | 1 |
| wikipedia | *(empty)* | 1 |
| airbnb | 1 | 3 |
| flipkart | 1 | 4 |
| spotify | 3 | 6 |
| atlassian | 2 | 5 |

**Fix (no new permissions):**
1. On `LIGHT_SCAN`, run the existing MAIN-world probe from the service worker, debounced per tab. Merge and cache the result as deep.
2. Never let a light result overwrite a deep one for the same URL.
3. Run one extra pass on `tabs.onUpdated status==='complete'` to catch late hydration.

### R2 — Rescan re-uses stale signals (High)
`deepScan` re-uses the cached light signals whenever the URL matches, so **Rescan** only refreshes globals. Late scripts, lazy widgets and a reload of the same URL are never re-collected. The empty state tells users to "Try Rescan after load", but Rescan can't pick up anything new.

**Fix:** always call `collectFromContent` in `deepScan`, falling back to the cache only on failure, and invalidate on every `status==='loading'`.

### R3 — The service-worker handler has no try/catch and no timeouts (High)
An exception in `detect()` or `applyBadge` means `sendResponse` is never called, and the popup shows a raw "message port closed" error. `executeScript` and `sendMessage` have no timeout, so a hung page leaves the popup on "Scanning…" forever.

**Fix:** wrap the handler in try/catch, add `Promise.race` timeouts (for example 3 s for the probe and 2 s for collection), and add an `AbortController`-style sequence number so an older Rescan can't render over a newer one.

### R4 — Navigation races and lifecycle gaps (High)
- **Popup opened mid-navigation:** it can merge the new document's signals under the old URL. Use the `signals.url` the content script reports, and retry once if it differs.
- **SPA `pushState`:** it only invalidates the cache; it never rescans or clears the badge, so the badge keeps showing the previous route.
- **bfcache and prerender:**
  - A page restored from the back/forward cache doesn't re-post, because there is no `pageshow` handler.
  - A prerendered document can overwrite the visible tab's badge. Gate `LIGHT_SCAN` on `sender.frameId===0 && sender.documentLifecycle==='active'`, and re-post on `prerenderingchange`.
- **After an extension update:** open tabs get no badge until they reload. Re-inject in `onInstalled`, and make sure the content script's "already loaded" guard doesn't block injection into a tab whose old copy is dead.

### R5 — Pages that can't be scanned look "empty" (Medium)
`file://`, the Chrome Web Store, the PDF viewer, `data:` and `blob:` pages fail silently. They show "No solid stack signals on this page" with **Wrong?** still enabled.

**Fix:**
- Return `error:'unreachable'` and show *"Chrome doesn't allow extensions to read this page."*
- Share one `isRestrictedUrl` between popup and service worker. They differ today: the popup's check misses `view-source:`.

### R6 — Strings and polish (Low)
- The tooltip says **"WhatStack: 1 stack signals"**. Fix the plural, and "signals" → "technologies".
- The Markdown export doesn't escape `|` or newlines in names, versions or URLs.
- The JSON export has no `schemaVersion`.
- The report body includes full asset URLs with query strings (clipped to 80 characters). Strip the query and fragment so the "origin only" promise also covers the evidence.
- Backticks aren't escaped in the report table.
- There is no `:focus-visible` style on rows and buttons.

### R7 — Content-script cost on huge pages (Low)
`querySelectorAll('body *')`, `[class*="sc-"]` and `[class]` build full NodeLists before the 300/200/80 caps apply. Use a `TreeWalker` with early exit.

`assetCandidates()` is recomputed for about 150 checks per scan. Compute it once.

## 5. Tests and tooling

- **134 tests pass, but every fixture is hand-written.** The MAIN-world probe (about 440 lines) is **never executed** by a test. Fixtures invent the `globals` it's assumed to return, so the two can drift apart unnoticed.
- **Per-signature coverage:** `CONTRIBUTING.md` requires a positive case and a prose-only case per rule.
  - **27 of 64 signatures** have no positive test, including Vite, Parcel, Turbopack, Clerk, Firebase, Datadog, LogRocket, Zendesk, Solid and Zustand.
  - About 32 have no prose-only negative.
- **No-op or conditional assertions:**
  - result-shape.test.js L42–65: the Tailwind "low" test only checks when Tailwind is low.
  - store-readiness L119–123: checks that a SHA-256 hex string has 64 characters, which is always true.
- **Browser suite:**
  - Hard-coded `headless:false`, fixed sleeps (2200/1500/900/600 ms) and a fixed port 8899.
  - Extension errors raised during the popup check don't fail the run.
  - It never checks the badge and never runs a real deep scan end to end.
- **No CI, lint, typecheck or coverage.** `npm test` also runs the packer, which shells out to `zip` and writes to `dist/`.
- **Audit scripts:**
  - `local-only-audit` checks only 6 of 10 shared files and misses `sendBeacon`, `WebSocket`, `EventSource` and image beacons.
  - `manifest-audit` misses side-effect and dynamic imports.
- **Docs out of date:**
  - The README's `CHROME_PATH` advice contradicts `run.mjs`.
  - The test counts in ENGINE-AUDIT, RELEASE and PRE-SUBMIT disagree.
  - The README layout section omits three shared modules.

## 6. What's already good (keep it)
- Evidence comes from URLs, globals and probed flags only, never `outerHTML` text. `dom-evidence.test.js` enforces this.
- React detection follows React DevTools: a registered renderer, not the bare hook.
- Low-confidence hits are separated in the UI ("verify before trusting").
- The report is a user-reviewed prefilled issue, carrying the origin only.
- The popup never uses `innerHTML`. The brand SVGs are bundled constants.
- The orchestrator is injectable and testable, and the LRU cache is capped.

## 9. Reproduction

To reproduce §3, run the crafted cases against `detect()` and run `mainWorldProbeSource()` in `node:vm` with fake globals. For example:

```js
detect({...empty, globals:{ next:{ present:true, version:'1.0.0-beta.9' } }})
// → nextjs:high@1.0.0-beta.9, react:high
detect({...empty, scripts:['https://x.com/img/logrocket-vs-zendesk.png']})
// → logrocket:high, zendesk:high
detect({...empty, inlineSamples:['{"title":"Migrating to single-spa and module federation with qiankun"}']})
// → module-federation, single-spa, qiankun, microfrontend: all high
```

Phase 5 turns each of these into a permanent test.
